# Admin usability requirements

The admin must be drop-dead easy to use. These are hard requirements, not polish:

- **No markup of any kind in input fields.** No Markdown, HTML or special syntax. Fields are plain text; the site applies all styling and formatting. Bios and descriptions are typed as ordinary paragraphs (a blank line starts a new paragraph, and the editor never asks the user to know that).
- **Plain-language labels and help text.** Say "Event name", not "title slug"; no jargon, IDs or technical error messages.
- **Pick, don't type, wherever possible.** Date and time pickers, photo upload by drag-and-drop or a big "Choose photo" button, toggles instead of status codes, up/down controls to reorder.
- **One obvious action per screen.** Large buttons, clear "Save" and "Cancel", and a visible confirmation after saving ("Saved. It's now on the website.").
- **A live preview** of how an item will look on the site, where practical.
- **Hard to break things.** Confirm before deleting, prefer "hide" over "delete", validate and explain problems in plain words next to the field, and resize/optimize uploaded images automatically.
- **Works on a phone and a desktop**, with large touch targets and readable text sizes.

## What the admin covers

Add, edit or hide an event and upload a poster; add or retire a DJ or host with a photo and schedule; reorder; edit partners; change the stream URL, links and site text. Every save is visible on the public site immediately.
